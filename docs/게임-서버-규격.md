# 모기 잡기 · 회원 · 랭킹 서버 규격 (2026-10-07)

팀장 피드백 3·4번(스테이지 게임, 수집형 배지, 회원가입·로그인, 닉네임 랭킹, 연말 보상, 어뷰징 방지)을 어떻게 만들었고, 서버(Supabase)를 어떻게 켜는지 적은 문서입니다. 서버 주체는 2026-10-07 결정대로 **Supabase**(저장소 주인 계정)입니다. 인제대 서버로 바꾸려면 "5. API 규격"만 그쪽에서 똑같이 구현하면 사이트는 그대로 씁니다.

## 1. 한눈에

| 구분 | 어디서 | 파일 |
| --- | --- | --- |
| 게임(스테이지·난이도·배지 카드) | 브라우저, 서버 없이 동작 | game.js, game-config.js |
| 숫자 설정(단계·난이도·배지 기준·보상·하루 제한) | 한 파일 | game-config.js (서버는 game_config 표) |
| 회원가입·로그인·로그아웃·기록 보내기 | 브라우저 → Supabase | auth.js |
| 서버 주소·공개 키 전달 | Vercel 함수 | api/public-config.js |
| 표·검증 함수·랭킹 표 | Supabase SQL | supabase/game-schema.sql |
| 내 배지·내 기록·계정 화면 | me.html, me.js | 메뉴 "내 배지", 폰 탭 6번째 |
| 랭킹 화면 | ranking.html, ranking.js | 홈 바닥글, 내 배지 화면에서 링크 |

서버가 없어도(지금) 게임·배지·내 기록은 그대로 되고, 계정·랭킹 칸만 "준비 중"으로 보입니다.

## 2. 게임 규칙 (game-config.js)

- **자유 모드**: 평소 첫 화면. 오늘 모기지수 단계만큼 모기가 떠 있고(매우 낮음 1 … 매우 높음 8), 잡으면 누적됩니다.
- **도전 모드**: 첫 화면 오른쪽 위 "도전" 버튼. 단계별 목표·제한 시간은 3마리/20초 → 10/40 → 30/75 → 100/150 → 300/300 → 1,000/600초. 오늘 모기지수 단계에 따라 열리는 단계 수가 다릅니다(낮음 3단계까지 … 매우 높음 6단계=1,000마리). 깬 단계의 다음 단계까지만 고를 수 있습니다.
- **난이도**: 단계가 오를수록 동시에 뜨는 마리 수(2→10), 도망 시작 거리(190→310px), 도망 세기, 옆으로 꺾기, 최고 속도(7.5→15)가 오르고 명중 반경은 줄어듭니다(1→0.8배). 휴대폰은 동시 마리 수 0.7배.
- **실패해도 누적 유지**: 제한 시간 안에 못 잡으면 실패 카드가 뜨지만 잡은 수는 누적에 남습니다. 성공하면 다음 단계 버튼.
- **배지 9개**(누적 기준): 알 10 → 장구벌레 30 → 번데기 60 → 모기 100 → 빨간집모기 200 → 작은빨간집모기 350 → 흰줄숲모기 500 → 얼룩날개모기 750 → 이집트숲모기 1,000. 단계마다 다른 그림의 임명장이 뜨고, 내 배지 화면에 모입니다. 시연: 주소 뒤 `?egg=larva` 처럼 배지 id 를 붙이면 카드가 바로 뜹니다.
- **저장**: 브라우저 localStorage `mz-game` (누적, 최고 단계, 배지, 오늘 도전 수, 최근 50건, 아직 서버에 못 보낸 기록). 로그인하면 서버와 합칩니다(큰 값 우선).

## 3. 서버가 안 터지게 한 것

1. 게임은 전부 브라우저 안에서 돕니다. 서버는 **도전이 끝날 때 한 번**(최대 20건 묶음) 받습니다. 한 마리마다 통신하지 않습니다.
2. 랭킹은 요청마다 계산하지 않고 `ranking_cache` 표를 **5분마다** 다시 만듭니다(pg_cron). 브라우저는 그 표만 읽습니다.
3. 브라우저가 쓸 수 있는 건 함수 `submit_game_runs` 하나. 표에 직접 쓰기는 RLS 로 막혀 있습니다.
4. 쓰기는 로그인한 사람만. 익명은 랭킹 읽기만.
5. 사이트 자체는 정적 파일 + CDN 이라 접속자가 늘어도 Supabase 쪽만 늘어납니다. 무료 플랜 기준 월 5만 활성 사용자·DB 500MB. 도전 기록 한 줄은 약 100B 라 1만 명이 하루 10번씩 1년 해도 3.6GB → **1년 지난 game_runs 는 지워도 됨**(누적은 game_scores 에 남음). 필요하면 `purge` 함수를 추가합니다.

## 4. 어뷰징 방지 (서버 함수가 검사, 어긋난 기록은 버리고 나머지만 받음)

| 검사 | 기본값 | 설정 위치 |
| --- | --- | --- |
| 하루 도전 횟수 | 30회 (서울 시간 하루) | game_config.daily_play_limit / DAILY_PLAY_LIMIT |
| 한 도전 분당 잡기 상한 | 150마리/분 | max_kills_per_min / MAX_KILLS_PER_MIN |
| 한 마리당 최소 시간 | 200ms | min_ms_per_kill / MIN_MS_PER_KILL |
| 단계 목표 초과 | 목표보다 많으면 거절 | stage_targets |
| 오래된 기록 | 48시간 지난 건 거절(오프라인 뒤 보내기 허용 범위) | max_run_hours |
| 미래 시각 | 10분 이상 앞서면 거절 | 고정 |

추가로 Supabase Auth 의 기본 요청 제한(가입·로그인 시도 횟수)이 있습니다. 더 필요하면: 기기당 계정 수(지문 수집이 필요해 개인정보 검토 뒤), 같은 IP 가입 제한(Supabase 설정).

## 5. API 규격 (인제대 서버로 바꿀 때 그대로 구현)

| 기능 | Supabase 에서 | 입력 | 출력 |
| --- | --- | --- | --- |
| 회원가입 | auth.signUp(email, password, {nickname}) | 이메일·비밀번호·닉네임(2~12자, 중복 불가) | 세션 (이메일 확인을 켜면 메일 확인 뒤) |
| 로그인 / 로그아웃 | auth.signInWithPassword / signOut | 이메일·비밀번호 | 세션 |
| 내 프로필 | profiles (id, nickname, role) | - | role 이 staff 면 전문가용 화면 |
| 기록 보내기 | rpc submit_game_runs(p_runs) | [{stage, kills, duration_ms, success, played_at}] ≤20건 | {accepted, rejected, total_kills, best_stage, badges[]} |
| 내 누적 | game_scores (user_id, season) | - | total_kills, best_stage, runs |
| 내 배지 | user_badges | - | [{badge_id, earned_at}] |
| 랭킹 | ranking_public (season) | - | [{rank, nickname, total_kills, best_stage, badge_count}] 상위 100 |

표: profiles · game_runs · game_scores · user_badges · ranking_cache · game_config (정의는 supabase/game-schema.sql).

## 6. 켜는 순서 (저장소 주인이 할 일)

1. Supabase 대시보드 → SQL Editor 에 `supabase/game-schema.sql` 붙여 넣고 실행.
2. Database → Extensions 에서 **pg_cron** 켜고, SQL 에서 `select cron.schedule('mz-ranking', '*/5 * * * *', $$select public.rebuild_ranking()$$);` 실행.
3. Authentication → Providers → Email: 켜기. "Confirm email" 은 처음엔 **끄는 것을 권장**(시민이 메일 확인 없이 바로 시작). 켜 두면 가입 뒤 메일 링크를 눌러야 로그인됩니다.
4. Vercel 환경변수 확인: `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_ANON_KEY` (Vercel–Supabase 연동이면 이미 있음). 없으면 Supabase → Settings → API 에서 복사해 넣기. 끄고 싶으면 `ACCOUNTS_ENABLED=0`.
5. 배포 뒤 `/api/public-config` 가 `{"enabled":true,...}` 를 주는지 확인 → 내 배지 화면에 가입·로그인 폼이 보이면 성공.
6. 직원 지정: SQL 에서 `update public.profiles set role='staff' where nickname='닉네임';` → 그 계정으로 로그인하면 내 배지 화면에 전문가용 링크가 보이고 expert.html 이 열립니다.
7. 연말 정산: 12월에 `ranking_public` 을 내려받아(CSV) 보상 구간(game-config.js REWARD_TIERS)대로 지급. 금액·범위가 정해지면 game-config.js 의 REWARD_TIERS·REWARD_NOTE 만 고칩니다.

## 7. 아직 안 정한 것 (설정값으로 빼 둠)

- 보상 금액·범위: `REWARD_TIERS`, `REWARD_NOTE` (지금은 "예시, 미확정" 표시)
- 하루 도전 횟수·속도 상한: `DAILY_PLAY_LIMIT`, `MAX_KILLS_PER_MIN`, `MIN_MS_PER_KILL` + 서버 `game_config`
- 시민용 화면 이름: `CITIZEN_PAGE_NAME` (지금 "자세히 보기")
- 닉네임 변경 허용 여부(지금은 불가), 카카오 로그인 추가 여부(Supabase 가 지원, 카카오 개발자 등록 필요)
- 개인정보 처리방침의 회원 항목 문구는 운영 기관 법무 검토 필요 (privacy.html 7번)
