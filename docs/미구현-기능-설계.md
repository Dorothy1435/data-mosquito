## 2. 켜기만 하면 되는 것 (✅)

### 2-1. 회원가입 · 로그인 · 로그아웃 · 랭킹

- **지금:** 브라우저 코드(`auth.js`), 계정 화면(`me.html`·`me.js`), 랭킹 화면(`ranking.html`), 서버 표·검증 함수(`supabase/game-schema.sql`), 공개 설정 함수(`api/public-config.js`)가 모두 있습니다. 서버 주소가 없어서 화면에 '준비 중'으로 보입니다.
- **방식:** 이메일 + 비밀번호 + 닉네임. 비밀번호는 Supabase가 보관하고, 사이트는 비밀번호를 보지 않습니다. 게임 기록은 도전이 끝날 때 한 번 보내고, 서버 함수가 말이 되는 기록인지 검사합니다.
- **켜는 순서 (계정 주인):**
  1. Supabase SQL Editor에서 `supabase/game-schema.sql` 실행
  2. pg_cron 켜기 (랭킹 5분마다 갱신)
  3. Authentication → Email: 확인 메일 끄기 권장 (켜 두면 가입 직후 로그인이 안 됨)
  4. Vercel 환경변수 `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_ANON_KEY` 확인 (Vercel–Supabase 연동이 자동으로 넣음)
  5. 직원 계정은 `profiles.role = 'staff'`로 지정하면 상단에 '전문가용' 버튼이 생김
- 자세한 규격: `docs/게임-서버-규격.md`

### 2-2. 사진 판별 (외부 AI)

- **지금:** 카메라 → 1024px로 줄이기(촬영 위치 정보 삭제) → `/api/identify` → AI가 5가지 중 하나로 답합니다. 5가지는 흰줄숲모기, 얼룩날개모기, 집모기류, 모기 아님, 알 수 없음입니다. 사진은 저장하지 않습니다.
- **막힌 이유:** 지금 있는 Groq 키에는 사진을 보는 모델이 없습니다.
- **할 일:** Vercel에 `GEMINI_API_KEY` 또는 `OPENAI_API_KEY`를 넣습니다. 그러면 코드 수정 없이 동작합니다.
- **비용 감:** 사진 1장당 몇 원 수준입니다. 공개 전에 12번의 AI 호출 한도를 꼭 같이 넣습니다.

### 2-3. 제보 저장

- **지금:** 빨간 '물렸어요' 버튼과 '여기 모기 있어요' 버튼이 같은 대화형 창을 엽니다. 위치는 GPS 1회 또는 동네 선택으로 정하고, 내 화면 지도에 점을 찍습니다. 서버(`api/report.js`)는 저장 스위치가 꺼져 있어서 저장하지 않습니다.
- **저장 방식(준비됨):** 위치를 약 100m로 반올림하고, 누가 보냈는지는 저장하지 않습니다. 공개 지도에는 동 단위 개수만 내보내고, 1년 뒤 삭제합니다(`supabase/schema.sql`).
- **켜기 전 필수 (행정):**
  - 위치기반서비스사업 신고 (방송통신위원회)
  - 개인위치정보 이용약관과 동의 문구 확정
  - 보관 기간 확정
  - `privacy.html` 빈칸 채우기
- **켜는 법:** Vercel 환경변수 `REPORT_STORE_ENABLED=1`, `supabase/schema.sql` 실행.

## 3. 개발이 필요한 기능 (🛠)

### 3-1. 제보에 '언제 · 몇 군데' 저장 (작음, 반나절)

### 3-2. 보건소 제보 확인 화면 (중간, 2~3일)

- 확인된 고인 물 제보는 지도에 '방역 필요'로 따로 표시합니다.

### 3-3. 식중독지수 식약처 연동 (작음, 1일 + 키 발급 기다림)

- **지금:** 기온·습도로 자체 산출하고, 화면에 '자체 산출'로 표시합니다. 회의에서 "식약처 연동"이라고 했지만 아직 연동되어 있지 않으므로, 연동 전에는 식약처 출처를 표기하지 않습니다.
- **할 일:**
  1. 공공데이터포털에서 '식품의약품안전처 식중독지수' API 활용 신청 (담당자)
  2. 서버 함수 `api/food.js`가 인증키로 받아 30분 캐시
  3. `computeFoodPoisoningIndex()`를 이 값으로 교체하고 표시를 '자체 산출' → '식약처'로 변경
  4. 실패하면 지금의 자체 산출값으로 돌아가고 '자체 산출'로 표시
- 인증키는 서버 환경변수에만 둡니다. API 응답 형식은 키를 받은 뒤 실제 응답을 보고 맞춥니다.

## 4. 기획부터 할 것 (🧭)

### 4-1. 뜀박수 (슬로우 조깅 걸음 수)

**왜:** 만보기는 어느 앱에나 있습니다. 모기는 땀과 이산화탄소에 반응하므로, "땀이 나는 활동만 센다"는 규칙 자체가 앱 취지를 설명해 줍니다.

**핵심 판단:** 슬로우 조깅은 걷는 속도(시속 4~6km)로 뛰는 운동이라 **속도로는 걷기와 구분이 안 됩니다.** 대신 **발걸음 빠르기(케이던스)**로 구분합니다. 걷기는 분당 약 100~120걸음, 슬로우 조깅은 약 180걸음입니다.

| 정할 것 | 추천안 |
|---|---|
| 집계 기준 | 분당 140걸음 이상이 30초 이상 이어질 때만 셈. 시속 20km를 넘으면 제외(자전거·차) |
| 측정 (웹, 1단계) | '뛰기 시작' 버튼 → 화면 켜 두기(Wake Lock) → 휴대폰 흔들림 센서로 걸음, GPS로 속도. 화면이 꺼지면 멈춤. 아이폰은 센서 사용 허락 창이 뜸 |
| 측정 (앱, 2단계) | 휴대폰 만보기·헬스 앱(안드로이드 Health Connect, 아이폰 HealthKit)에서 가져오기. 워치도 여기서 연동. 화면이 꺼져도 셈 |
| 저장 | 이동 경로는 휴대폰 안에서만 쓰고 서버에는 **하루 합계(걸음 수·분)만**. 위치를 저장하지 않으므로 제보보다 부담이 적음 (법률 확인은 필요) |
| 어뷰징 | 하루 상한(예: 3만 걸음), 분당 220걸음 넘으면 버림, 서버 함수가 검사 (게임과 같은 방식) |
| 랭킹 | 기존 랭킹 화면에 '뜀박수' 탭. 월간 + 연 누적, 연말 리워드와 연결 |
| 이름 | 뜀박수 (확정 필요) |

**결정 필요:** 웹으로 먼저 만들지(화면을 켜고 폰을 들고 뛰어야 함), 앱 출시 때로 미룰지.
**규모:** 웹 1단계 약 1주(센서·화면·서버 표·랭킹 탭), 앱 2단계는 앱 출시와 함께.

### 4-2. 리워드 (해외여행 키트)

- **품목 예시 (기내 반입 가능, 3~5만 원):** 100ml 이하 기피제, 모기 패치, 휴대용 손소독제, 물린 데 바르는 연고, 쿨토시·접이식 모자. 질병청 키트(약 3.5만 원)를 참고합니다.
- **지급 조건 후보:** 뜀박수 월간 상위 N명 / 게임 랭킹 상위 / 제보 참여자 추첨
- **연락처:** 당첨자에게만 그때 따로 받고(별도 동의), 발송 뒤 바로 삭제합니다. 회원가입 때는 받지 않습니다.
- **먼저 확인할 것:** 지자체·보건소가 주민에게 경품을 주는 것이 예산 집행 규정과 공직선거법의 기부행위 제한에 걸리지 않는지, 근거(조례·사업 예산)가 있는지 담당 부서에 확인합니다.
- `game-config.js`의 `REWARD_TIERS`(지금은 '예시, 미확정' 상품권)를 확정안으로 바꿉니다. 피드백에 따라 상품권은 초기 제외합니다.

## 5. AI 모델 ① 모기 개체수 예측 모델 v6

### 지금 (v5)

- 김해 MOSCOM 트랩 실측 694건(178개 지점, 2025-05 ~ 2026-09)으로 학습했습니다. 구성은 그래디언트 부스팅 250트리(기상 22개 + 낮 길이 3개 변수)와 공간모형(발생원·인구·하천)입니다.
- 정확도(교차검증): 처음 보는 지점 스피어만 0.65, 처음 보는 기간 0.68 (v4는 0.22)
- 사이트 연결: `api/model.py`가 `mosquito_model_portable.py`를 불러 17개 동 값을 30분 캐시합니다.

### 한계

1. **김해 밖은 모델이 없습니다.** 경남 17개 시·군은 날씨로만 추정합니다.
2. 실측이 한 시즌 반뿐이라 해마다 달라지는 정도(장마, 폭염 해)를 아직 모릅니다.
3. 시민 체감(물림)과 트랩 채집수의 관계를 확인하지 못했습니다.

### v6 설계

| 평가 | 처음 보는 지점·기간 교차검증 스피어만 0.7 이상 목표, 시·군별로 따로 보고 |
| 재학습 | 시즌 끝(10월)에 한 번 + 시즌 중간(7월)에 한 번. 모델 파일만 바꾸면 사이트가 그대로 반영(반환 키 유지) |
| 필요한 것 | 트랩 자료 공유 협조(경남도·시·군 보건소), 소다맵 자료 공개 사용 서면 승인, 모델 담당자 시간 |

## 6. AI 모델 ② 사진 판별 자체 모델

### 왜 자체 모델인가

- 외부 AI는 사진 1장마다 비용이 들고, 사진이 외부 회사 서버로 갑니다.
- 자체 소형 모델을 **휴대폰 브라우저 안에서** 돌리면 사진이 밖으로 나가지 않습니다. 개인정보 걱정과 비용이 모두 0이고, 인터넷이 약해도 동작합니다.

### 설계

| 항목 | 내용 |
|---|---|
| 맞힐 것 | 지금과 같은 5가지: 흰줄숲모기 · 얼룩날개모기 · 집모기류 · 모기 아님 · 알 수 없음(확신이 낮으면) |
| 학습 사진 (목표: 종마다 500~1,000장) | ① 공개 자료: Mosquito Alert(시민 모기 사진, 전문가 확인 라벨), iNaturalist 연구 등급 사진 — **둘 다 사진마다 라이선스(CC BY 등)를 확인해 허용된 것만** ② 보건소 채집 표본 촬영(현미경·휴대폰, 라벨 확실) ③ 시민 사진 기증(별도 동의, 촬영 위치 삭제) |
| 모델 | 이미지넷으로 미리 배운 작은 모델(MobileNetV3 또는 EfficientNet-Lite)에 모기 사진을 더 학습(전이학습). 크기 5~10MB |
| 돌리는 곳 | 브라우저(ONNX Runtime Web 또는 TensorFlow.js). 처음 한 번 내려받고 이후에는 저장분 사용 |
| 판정 규칙 | 가장 높은 확률이 0.6 미만이면 '알 수 없음'. 빨간집모기와 작은빨간집모기는 사진으로 구분이 어려워 '집모기류'로 묶음(지금과 같음) |
| 평가 | 따로 떼어 둔 사진으로 종별 정밀도·재현율. 특히 흰줄숲모기(뎅기)와 얼룩날개모기(말라리아)를 놓치지 않는지 확인. 목표 정확도 85% 이상 |
| 도입 순서 | 1단계: 외부 AI(지금 코드)로 공개 → 2단계: 자체 모델을 함께 돌려 결과 비교(화면엔 외부 AI만) → 3단계: 자체 모델이 비슷하거나 나으면 전환, 외부 AI는 '알 수 없음'일 때만 |
| 필요한 것 | 학습용 PC(GPU 있으면 좋음, 없으면 무료 Colab), 보건소 표본 촬영 협조, 사진 기증 동의 문구 |
| 규모 | 사진 모으기가 가장 오래 걸림(1~2개월). 학습·브라우저 연결은 1~2주 |

## 6-1. 사진 포인트 · 랭킹 3종 (2026-10-08 김해보건소 팀장 피드백)

**요청:** 사진으로 매개모기(일본뇌염·말라리아)로 판정되면 포인트를 준다. 찍은 위치(위경도)를 자동으로 붙여 분포 자료로 쓴다. 랭킹은 모기 잡기 · 사진 포인트 · 뛰어런(km 또는 걸음 수)을 따로 10명씩 뽑는다.

**먼저 짚을 점**

1. **일본뇌염 매개모기는 '작은빨간집모기'입니다.** 빨간집모기는 웨스트나일열 쪽입니다. 그런데 둘은 사진으로 구분이 어려워, 지금 판별은 '집모기류'로 묶어 답합니다. 그래서 "일본뇌염 모기 사진 = 포인트"를 정확히 하려면 모델 ②(자체 모델)에서 두 종을 나눌 수 있는지 먼저 시험해야 합니다. 그 전에는 '집모기류'에 포인트를 줍니다.
2. **위치 저장은 제보 저장(2-3)과 같은 절차가 필요합니다.** 위치기반서비스사업 신고와 개인위치정보 동의입니다. 지금 사진 판별은 사진 속 위치 정보(EXIF)를 지우도록 되어 있으므로, 사진 파일의 위치가 아니라 **찍을 때 휴대폰 GPS를 한 번 받아 약 100m로 반올림**해 판정 결과와 함께 저장합니다(사진은 저장하지 않음).
3. **포인트가 걸리면 부정행위가 생깁니다.** 인터넷 사진을 다시 찍기, 같은 사진 반복 등이 예상됩니다. 그래서 아래 방지책이 필요하고, **보상 대상(상위 10명)은 보건소가 확인**할 수 있어야 합니다. 확인하려면 포인트를 받은 사진만은 동의를 받아 보관해야 합니다(결정 필요).

**설계**

| 항목 | 내용 |
|---|---|
| 포인트 (예시, 확정 필요) | 얼룩날개모기 30점 · 집모기류 10점 · 흰줄숲모기 20점(뎅기, 기후변화 감시에 같이 쓰기 권장) · 모기 아님/알 수 없음 0점. AI 확신도 '낮음'이면 0점 |
| 조건 | 로그인한 사람만 포인트. 위치 동의를 하면 포인트 지급(분포 자료가 목적이므로) |
| 저장 (서버 표 `photo_finds`) | 사용자 id, 판정 종, 확신도, 위경도(100m 반올림), 동, 시각, 사진 지문(같은 사진 막기용 해시), 보건소 확인 상태. 사진 원본은 '보관 동의' 시에만 |
| 부정 방지 | 하루 포인트 상한(예: 10장), 같은 사진 지문 재사용 0점, 같은 자리 1분 안 연속 0점, 카메라로 바로 찍은 것만(앨범 업로드는 판별만 하고 포인트 없음), 상위 10명은 보건소 확인 뒤 확정 |
| 분포 자료 | 보건소 화면에 종별 점 지도와 동별 주간 개수. 시민 공개 지도에는 동 단위 개수만 |
| 랭킹 3종 | 모기 잡기 10명 · 사진 포인트 10명 · 뛰어런 10명(km 또는 걸음 수 중 결정). 기존 랭킹 화면에 탭 3개. 각각 월간 + 연 누적 |

**결정 필요:** 종별 포인트, 흰줄숲모기 포함 여부, 포인트 사진 보관 여부, 뛰어런을 km와 걸음 수 중 무엇으로 셀지, 이름('뛰어런'·'뜀박수').
**규모:** 위치 절차가 끝났다는 전제로 약 1주(서버 표·검증 함수, 사진 판별 뒤 포인트 흐름, 랭킹 탭 3개, 보건소 확인 화면에 사진 탭).
